Install Instructions

Re-installing or updating the root? Remove any older Lanbat Root CA first. Every generation shares the same name, so stores can keep trusting an old key unless you delete it — browsers then report errors such as "invalid signature".

System trust store

Debian / Ubuntu / NixOS (run as root):

# Remove any previous Lanbat root (same CN → same hash slot)
rm -f /usr/local/share/ca-certificates/lanbat-ca.crt
curl -k PLACEHOLDER_CA_ORIGIN/lanbat-ca.crt -o /usr/local/share/ca-certificates/lanbat-ca.crt
update-ca-certificates

Fedora / RHEL:

rm -f /etc/pki/ca-trust/source/anchors/lanbat-ca.crt
curl -k PLACEHOLDER_CA_ORIGIN/lanbat-ca.crt -o /etc/pki/ca-trust/source/anchors/lanbat-ca.crt
update-ca-trust

On NixOS (add to configuration.nix):

security.pki.certificateFiles = [ /etc/ssl/certs/lanbat-ca.crt ];
CLI tools only. update-ca-certificates does not affect Firefox or Chrome — configure browsers separately below.

Firefox and Chrome / Chromium / Brave

These browsers use their own NSS databases on Linux, not the system store.

GUI (Firefox): Settings → Privacy & Security → Certificates → View Certificates → Authorities → remove any old Lanbat Root CA → Import the downloaded lanbat-ca.crt → check "Trust this CA to identify websites" → OK. Restart Firefox.

Terminal (certutil is in libnss3-tools on Debian/Ubuntu):

# Download first, then (replace <profile> with your profile dir):
curl -k PLACEHOLDER_CA_ORIGIN/lanbat-ca.crt -o ~/lanbat-ca.crt

# Firefox — native package (~/.mozilla/firefox/<profile>/)
certutil -d sql:~/.mozilla/firefox/<profile> -D -n "Lanbat Root CA" 2>/dev/null || true
certutil -d sql:~/.mozilla/firefox/<profile> -A -n "Lanbat Root CA" -t "C,," \
  -i ~/lanbat-ca.crt

# Firefox Snap: ~/snap/firefox/common/.mozilla/firefox/<profile>/
# Firefox Flatpak: ~/.var/app/org.mozilla.firefox/.mozilla/firefox/<profile>/

# Chrome, Chromium, Brave (shared NSS db)
certutil -d sql:~/.pki/nssdb -D -n "Lanbat Root CA" 2>/dev/null || true
certutil -d sql:~/.pki/nssdb -A -n "Lanbat Root CA" -t "C,," -i ~/lanbat-ca.crt

Restart the browser after importing.

Option 1 — GUI:

  1. Download lanbat-ca.crt above.
  2. Open Keychain Access → search for Lanbat Root CA → delete any old copy.
  3. Double-click the new file → add to System keychain.
  4. Find the certificate, double-click → Trust → Always Trust.

Option 2 — Terminal:

curl -k PLACEHOLDER_CA_ORIGIN/lanbat-ca.crt -o ~/Downloads/lanbat-ca.crt
sudo security delete-certificate -c "Lanbat Root CA" /Library/Keychains/System.keychain 2>/dev/null || true
sudo security add-trusted-cert -d -r trustRoot \
  -k /Library/Keychains/System.keychain ~/Downloads/lanbat-ca.crt

Run in PowerShell as Administrator:

Invoke-WebRequest -Uri PLACEHOLDER_CA_ORIGIN/lanbat-ca.crt `
  -OutFile "$env:TEMP\lanbat-ca.crt" -SkipCertificateCheck
Get-ChildItem Cert:\LocalMachine\Root |
  Where-Object { $_.Subject -match 'Lanbat Root CA' } |
  Remove-Item
Import-Certificate -FilePath "$env:TEMP\lanbat-ca.crt" `
  -CertStoreLocation Cert:\LocalMachine\Root

Or manually:

  1. Download lanbat-ca.crt.
  2. Open certmgr.msc → Trusted Root Certification Authorities → Certificates → remove any old Lanbat Root CA.
  3. Right-click the new file → Install Certificate.
  4. Store location: Local Machine.
  5. Place in: Trusted Root Certification Authorities.
  1. Scan the QR code above or download the cert via browser.
  2. If updating: Settings → Security → Encryption & Credentials → Trusted credentials → User → remove any old Lanbat Root CA.
  3. Go to Settings → Security → Encryption & Credentials → Install a Certificate.
  4. Choose CA Certificate.
  5. Select the downloaded .crt file.
  6. Accept the warning.
Note: On Android, user-installed CAs are not trusted by all apps by default (Chrome works; many apps enforce system trust only). This is an Android security policy — nothing we can change.
  1. Scan the QR code above → Safari opens the cert download.
  2. Tap Allow to download the profile.
  3. Go to Settings → General → VPN & Device Management.
  4. Remove any older Lanbat CA profile, then tap the new profile → Install.
  5. Go to Settings → General → About → Certificate Trust Settings.
  6. Enable full trust for Lanbat Root CA (required — install alone is not enough).
Easy to miss: step 6 is mandatory on iOS. Without it the profile is installed but Safari still warns.

Verify it worked

After installing in your browser (and restarting it), open the homepage or run: 

curl -sS -o /dev/null -w '%{http_code}\n' PLACEHOLDER_VERIFY_URL

You should see 200 with no certificate warning. Or reload PLACEHOLDER_VERIFY_URL in the browser — the padlock should be valid.
